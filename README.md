# 短剧分镜渲染器 · Storyboard Renderer

把 LLM 输出的**结构化分镜 JSON**，渲染成一份可以直接交给制片的**单文件 HTML 分镜表**。

零第三方依赖，Python 3.8+，`python build_storyboard.py <项目目录>` 一条命令出结果。

> 示例成品：[`examples/审判日号_运河切割/分镜表_审判日号_运河切割_12镜.html`](examples/审判日号_运河切割/分镜表_审判日号_运河切割_12镜.html)（双击即可打开，无需服务器）

---

## 为什么拆成两段

| 端 | 负责 | 不负责 |
|---|---|---|
| LLM（Coze） | 理解剧本、设计景别节奏、写英文提示词、输出 JSON | 排版、配色、交付格式 |
| Python（本仓库） | 读 JSON → 渲染 HTML | 创作、判断镜头好坏 |

拆开的理由很简单：**创作要模型，排版要确定性。**

如果让模型直接吐 HTML，改一次样式就要重跑一次模型，而且每次版式都不一样。拆开之后，换剧本只替换 `data.json`，渲染器一行不动——这是我在这里唯一想强调的设计判断。

---

## 用法

```bash
# 仓库根目录执行
python build_storyboard.py examples/审判日号_运河切割
```

输出：

```
examples/审判日号_运河切割/分镜表_审判日号_运河切割_12镜.html
```

终端会打印一行自检信息，方便核对：

```
written: ...\分镜表_审判日号_运河切割_12镜.html
shots: 12 | sizes: {'大远景': 3, '全景': 4, '中近景': 1, '特写': 2, '中景': 1, '近景': 1} | dialogue: 0 | patched: 4
```

## 输入

一个项目一个目录，里面放两个文件：

```
examples/审判日号_运河切割/
├── meta.json   # 元信息：标题、场景、人物、情绪线、视觉基调
└── data.json   # 镜头数组
```

### meta.json

| 字段 | 说明 |
|---|---|
| `title` / `subtitle` / `eyebrow` | 标题区三行文字 |
| `logline` | 故事线一句话（渲染在页首导语） |
| `file_name` | 输出 HTML 的文件名 |
| `kv` | 二维数组，渲染成「场景与人物」的定义列表 |
| `footnote` | 页脚备注 |

### data.json

```json
[
  {
    "镜号": 1,
    "景别": "大远景",
    "画面描述": "清晨的巴拿马运河，薄雾贴着水面……",
    "台词": "（无）",
    "声音": "低沉引擎声、水流擦过船壳的闷响",
    "Midjourney英文提示词": "Wide aerial establishing shot, ... --ar 16:9 --style raw"
  }
]
```

| 字段 | 说明 |
|---|---|
| `镜号` | 从 1 起，用于索引与锚点 `#shot-01` |
| `景别` | 大远景 / 远景 / 全景 / 中景 / 中近景 / 近景 / 特写 / 大特写；其他值归入 wide |
| `画面描述` | 中文画面说明 |
| `台词` | 无台词写 `（无）`——渲染器据此判断本片有没有对白 |
| `声音` | 音效与环境声 |
| `补镜` | 可选，原文未明写、按镜头语言补足的镜头，会打「补」标记 |
| `Midjourney英文提示词` | 完整提示词，含 `--ar 16:9` 等参数 |

---

## 输出

- **单文件 HTML**：CSS/JS 全部内联，不依赖 CDN，断网也能开
- **景别分布条形图**：按「大远景 → 特写」固定顺序排序，避免字典序乱序
- **镜头卡片**：镜号、景别色标、画面描述、台词、声音、补镜标记
- **提示词折叠 + 一键复制**：制片/美术按镜取用，不用手抠文本
- **顶部镜号索引**：点 `01` 直接跳到第 1 镜
- **展开全部 / 收起全部**：审片时用

## 已验证

- 样例项目：12 镜，景别构成 `大远景3 · 全景4 · 中景1 · 中近景1 · 近景1 · 特写2`，补镜 4 个，无对白场景正确处理
- 另一项目：200 字剧本 → 14 镜，五个必填字段无缺失，可直接交付
- 渲染器：376 行，纯标准库（`json` / `html` / `os` / `sys`）

## 已知边界（没做的事）

这些是有意留白的，不是遗漏：

1. **不生成图片**：到「提示词」为止，不调 Midjourney/ComfyUI API
2. **不校验镜号连续性**：镜号必须从 1 连续；不连续会跳错锚点，目前不做纠正
3. **不做 PDF/PPT 导出**：要交付就给 HTML 加打印样式
4. **景别词表是硬编码的**：8 个值之外一律兜底为 wide，不做模糊匹配
5. **不做分镜合理性判断**：景别节奏、台词密度是否合理，还是得人看

第 5 条是我最想说明的——**这个工具只保证「不丢信息、排版一致」，不保证「分镜好」。** 判断镜头语言对不对，仍需要人。

> 每个决定背后的取舍和代价，写在 [`docs/design-notes.md`](docs/design-notes.md)。

## 为什么公开这个

渲染端不含任何平台交互逻辑、不含业务数据、不含客户素材；样例剧本为虚构。公开它只是想说明一件事：**我倾向于把「确定性的部分」写成代码，把「需要判断的部分」留给人。**
